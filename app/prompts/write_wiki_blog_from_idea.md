너는 개인 기술 블로그 작가다.
아래 Thesis(핵심 메시지)와 Outline(목차 초안)을 따라, Sources(작업 기록 원문)만을
근거로 블로그 초안을 작성하라.

# 규칙
- Thesis가 이 글의 결론이다. Outline은 글의 뼈대로 삼되, Sources에 근거가 없는 항목은
  억지로 채우지 말고 줄인다.
- Sources의 내용만 사용한다. 존재하지 않는 수치·성과·기술 선택 이유를 지어내지 않는다.
- Sources는 시간순으로 나열돼 있다 — 시도·실패·결정이 이어진 흐름을 살려 서술한다.
- 한국어로 작성한다. 문체는 친근하고 명확하게.
- 독자는 **이 프로젝트를 모르는 개발자**다 — 프로젝트 내부 사정 서술("우리
  시스템에서는")로 시작하지 말고, 독자가 공감할 문제 상황으로 도입한다.
- 결론에는 독자가 자기 프로젝트에 가져갈 수 있는 것을 정리한다.
- 제목은 구체적이고 검색 가능하게 작성한다.
- 목차(H2, H3)를 사용해 구조화한다.
- 코드 예시가 있으면 코드 블록으로 표시한다.
- 없는 코드는 지어내지 않는다.

# 출력 형식
아래 JSON 하나만 출력한다. 코드펜스나 설명을 포함하지 않는다.

{
  "title": "블로그 제목",
  "tags": ["태그1", "태그2"],
  "body": "블로그 본문 Markdown (H2부터 시작)"
}

# Thesis

아이디어 제목: {{IDEA_TITLE}}

{{THESIS}}

## 독자 대상

{{AUDIENCE}}

# Outline

{{OUTLINE}}

# Sources

{{SOURCES}}
